# 查阅规则与父子目录授权

## 配置入口

管理端文档列表中，栏目、目录、文档的“…”或右键菜单进入权限设置。
查阅权限和管理权限分为两个页签。默认用表格显示授权对象、来源和生效范围，添加或编辑时才展开表单。规则编辑先确认，再保存整个权限设置；取消编辑不会写入配置。排除人员和实际名单按需展开，说明收在“规则说明”中。

- 同一条规则：多个部门之间为“或”，多个具体等级之间为“或”，部门与等级之间为“且”。选中部门包含下级部门。不选某一维度表示不限制该维度，但不能保存部门、等级都为空的条件规则。
- 多条规则：满足任意一条即可。指定用户是一条独立的授权规则；全员需要明确选择，含义是所有已登录用户。
- 排除人员优先于规则中的授权。超级管理员始终可以查阅和管理，绕过排除规则。普通管理员在管理端的管理权限不会自动授予用户端查阅或问答权限。
- 不配置任何规则：不授予普通用户查阅权限。不会把空列表解释成公开。

## 目录范围

每条规则默认勾选“同时授权下级目录及其文件”。

- 勾选：传递给使用上级设置的后代目录、文档。
- 不勾选：授权当前目录及其中直接存放的文档，不传给子目录和子目录中的文件。
- 下级设置了独立规则后，祖先规则不再越过该独立边界；“含下级”不等于强行覆盖独立子目录。

文档没有后代，不展示这个范围复选框。

## 使用上级设置与独立设置

未单独配置的目录、文档动态沿用上级设置。仅点击“使用上级设置”的复选框才会切换，点击旁边文字或空白不切换。

取消使用上级设置时，复制上级实际传递到本级的完整规则和排除名单作为编辑起点，可以删除、添加或调整。保存后，本级成为独立查阅边界，可以收紧范围，也可以授权给上级范围之外的用户；上级后续修改不会覆盖本级独立设置。

恢复使用上级设置并保存后，清除本级独立规则，重新动态沿用上级。已独立配置的更深层子目录不受这次切换影响。

批量编辑将统一替换所选对象的设置。初始显示第一项；切换独立时以各项上级实际范围的交集作为复制起点，避免把一项的授权意外放到另一项。

## 只授权子目录或单份文档

允许不给父目录授权，单独授权下级目录或文档。用户端目录树显示通往授权内容的祖先路径节点，名称正常显示、可以展开导航。路径不授予父目录的文件、正文、附件或权限配置权，同级无权内容不显示。

目录树、文档访问、预览/下载校验、问答检索后的资料过滤、助手取材使用同一个有效查阅判定。修改权限后，新请求按当前规则计算；现有的目录树版本机制负责后续同步。已经显示在浏览器中的内容不能被远程收回。

## 历史配置与发版

新模型以现有 JSONB `permissions` 内的 `reading_version: 2` 标识，不需要数据库迁移，不修改账号、业务文档、原文件或向量索引，不需要重新学习。

已有历史权限在未修改保存前继续使用原有的父子收紧逻辑，避免发版时批量改变可见范围。历史复合条件转换为一条完整的组合规则，不拆成“或”规则；界面允许保留或删除它，也可以新增清晰的规则替换。转换时保留原有排除名单与最低等级约束。修改保存后才采用新的独立边界逻辑。

本次需要同时更新后端 API 和管理端。生产使用 `deploy/server/deploy.sh upgrade backend` 和 `deploy/server/deploy.sh upgrade admin`，遵循项目原有备份及保留数据卷流程。本次没有修改用户端前端代码。

## 本地回归

- 规则部门/等级的交集、规则之间并集、指定用户、排除优先、需要登录、空规则拒绝、超级管理员兜底。
- 当前目录/直接文件/多层后代的范围区别，独立子目录覆盖上级、恢复继承、栏目范围、批量预览交集。
- 在独立 PostgreSQL 测试库中保存与回读新权限；验证完整及逐层目录树、路径节点、无权同级隐藏、文档访问守卫、助手资料访问守卫、权限预览与实际结果一致。
- 历史权限、管理委派及树查询数量回归；前端类型检查及复制/转换规则测试。

本地测试使用临时测试库及回滚事务，不向业务知识库插入测试文档、不请求模型或 OSS。没有连接生产环境执行验证。

# 用户端助手体验改进与验收

目标：用户通过同一对话入口提问、提供资料、生成 Word/PPT/Excel、预览与连续修改；系统主动完成可完成的工作，只有影响交付的缺失信息才需要用户介入。进度和来源真实，权限不放宽，不以隐藏错误代替完成任务。

参考官方公开资料（2026-11-03）：

- [ChatGPT 文件工作流](https://learn.chatgpt.com/docs/artifacts-viewer?surface=app)：在对话与文件视图之间审阅和继续修改。
- [Claude 文件创建](https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude)、[Artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)：自然语言创建并迭代文件、预览及导出。
- [Kimi PPT 用户指南](https://www.kimi.com/academy/slides-intro)：资料/模板输入、生成、预览、多轮修改与导出。
- 豆包官网在本次抓取中不可达，未将其未核实的内部流程、额度或实现方式作为依据。上述产品的宣传功能不等于本项目已实现。

## 本轮验证记录

- 真实模型仅接收合成产品事实，三页分段样例两次通过，耗时约28秒、40秒，并在本地输出PPT。不代表生产规模时延，也不代替业务内容验收。
- 本地Office流水线验证了分段三页PPT加来源页、分段两节Word、23份完整Excel目录的生成、内存私有存储、下载和正文重读。
- 第二页中断后重新读取数据库检查点，只调用模型生成剩余两页；改材料使旧缓存失效。撤权后不展示草稿，取消后不再调用模型，认证类永久错误不反复重试。
- 前后端共享20条自然语言回归样例；支持“做个PPT、整理成Excel、导出成Word”等说法，“如何制作”等说明问题不强制生成文件。
- 实际进度组件已做本地浏览器展开、收起及截图验收，使用合成数据。这不等于整个登录会话已完成端到端验收。
- 直接任务API本地探测为1次任务请求、0次额外网站信息查询，并保持匿名401拒绝。带门户前缀路径保留原处理。
- 原库9个栏目、180个节点、16名用户和Postgres实际挂载保持一致；没有新增迁移、启动索引Consumer或连接生产。

## 连续修改与排版验证补充

- 文件元数据在复查来源权限后返回页/章节目录；跨账号和来源撤销后仍拒绝读取目录。预览旁可选修改范围，切换版本清空旧范围；实际组件浏览器合成样例操作通过。
- Word/PPT支持指定部分、连续范围和间隔选页；不明确的“这一页”等要求先明确范围。文件解释返回文字，不生成新文件；删除指定部分保留其余部分，拒绝删除全部正文。
- 真实Office合成流水线验证只修改第三页、下载并重新解析结果、从旧版另存新文件，以及原文件下载字节保持不变。Excel尚无同等范围的精确编辑保证。
- 默认PPT对简短要点分组排版，密集列表明确段落字号和固定行距，消除占位符继承大行高导致的页面裁切。企业PPT模板保留原版式。密集单页420字样例实际PDF检查无裁切，忽略换行后105个完整测试词组全部保留。
- Word默认A4中文样式、页码、按内容分配表格列宽、跨页重复表头，并避免拆分同一记录。40行合成表格实际PDF为2页，第二页从完整记录开始，表头和页码正常。
- 生成服务10项安全/格式/排版回归通过；本地更新保留原Compose项目，未挂载或删除业务卷。截图和合成Office/PDF保存在本地 `.local-data/assistant-preview/`，不属于真实业务内容验收。
- 本地126份发布文档中，35份明确仅元信息、16份记录全文解析、75份没有解析范围记录。未记录并不等于没有正文；没有据此重建索引或覆盖原文档。
- 登录页不再发送需要身份的页面统计，非关键统计失败有明确Promise处理。本地匿名登录页200，新增页面统计请求0；TypeScript检查和7项助手前端回归通过。

## 真实资料验收（2026-11-04）

用户授权由助手选择本地资料，并使用项目当前模型实际验收。选用已发布的《方案及产品合作信息清单.xlsx》，约2900字完整正文，有产品名称、功能和版本，没有客户案例或报价。

- 当前模型实际生成6页数字孪生正文和1页系统来源页，覆盖工厂级、产线级、装备级及两类支撑平台。人工对照原文并逐页检查本地PDF；产品版本、主要功能和“30多种数据源”有原文依据，没有新增客户案例或性能百分比。部分页面仍偏密集，默认排版仍有提升空间。
- 初轮发现比较表过长会多一次格式修正，已在生成提示中明确单元格60字、整页420字限制；明确事实与建议的边界，避免把推导的产品组合关系当作资料事实。
- 发现逐页阅读会重复附加请求中已有的全文。现在按当前请求中的实际文本去重；不是凭历史“已读”标记跳过，仍先校验来源权限和固定版本哈希。节选输入仍会补读原文。
- 初轮“精简为两点、每点不超过45字”没有完全遵守。增加用户明确要求的点数/字数校验、带实际字数的修正反馈和有界恢复；不截断正文冒充精简。最终第三页为42字和38字两个要点，原标题、其余页面和原始规范保持一致。
- 验收复用同一份已生成草稿进行修订，避免反复生成六页。最终使用实际编辑流程共用的提示，单页编辑约56秒，未触发格式重试。此前有6000 token耗尽但正文为空的响应，不能宣称模型服务的等待与截断问题已彻底解决。
- 针对已知Qwen3.6兼容接口，需求规划和局部编辑适配官方直接回答参数与推荐采样参数；兼容网关可转发两种参数名，明确拒绝扩展参数时仅回退一次。普通问答和其他模型保持原配置。一次规划约29秒，前两次约83秒；样本不足，不作为稳定性能承诺。参考[Qwen官方模式说明](https://huggingface.co/Qwen/Qwen3.6-27B#instruct-or-non-thinking-mode)。
- 所有验收任务和源正文副本处于回滚事务，渲染与PDF预览走本地服务，不读写真实OSS，不领取业务/索引队列。本轮证明内容链路，不证明原文档ACL和登录浏览器全链路；后两者仍需独立验收。
- 最终助手回归在仅复制表结构的专用测试库通过，API/Worker入口编译通过。本地样例和诊断文件位于忽略目录 `.local-data/assistant-preview/`，不提交业务正文。

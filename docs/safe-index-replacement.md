# 重新学习时保留正在使用的索引

## 单篇文档

- 创建独立索引版本和独立 RAG 文档，不复用当前用于问答的文档 ID。
- 解析得到的正文、解析范围等信息先保存在新版本中，不提前覆盖发布版本，避免本地检索备用流程读到未生效的内容。
- 排队、解析、上传以及 RAGLite 索引处理中，问答继续使用原来的有效版本。
- 只有 RAGLite 返回 `SUCCEEDED`，且任务未失败、取消、超时或被更新版本替代时，才在同一 PostgreSQL 事务中切换文档 ID、解析正文、生效指针和任务状态。
- 收到重复消息、迟到的失败/成功消息或服务重启，都不能让旧任务覆盖更新版本。
- 失败或取消保留原来的可用索引。首次学习没有旧索引时，不能提供“继续使用旧索引”的保障。
- 成功切换后，原单篇索引至少保留 10 分钟，再由状态同步任务清理；清理失败会重试，且不会删除仍被生效指针引用的文档。

问答会过滤未生效、失败、取消和已替换的版本。检索先多取候选，再只使用至多 10 个有效片段，避免新旧重复版本同时进入回答。必要时，本地检索使用原生效发布版本的正文。

## 向量模型变化引起的全量重建

1. 新建独立的向量模型配置记录和数据集，显式绑定新模型；不改写旧数据集引用的向量模型配置。
2. 按已发布的知识库快照创建普通学习任务，在现有“后台任务”中展示，由原有并发调度器处理，不再静默直接发送全部消息。
3. 保持知识库的当前数据集不变，问答继续使用旧模型和旧索引。
4. 每篇文档成功后仅标记“新索引已就绪，等待整批切换”。全部文档成功，且已发布快照、当前向量模型配置都没有变化时，在一个事务中整体切换数据集和全部生效文档指针。
5. 任一文档失败或取消，则整批不切换，停止尚未提交的任务并保留原索引。已经提交到 RAGLite 的工作可能继续执行，但其迟到结果不能生效。
6. 索引配置基准只在成功切换后更新。保存表单不能把一个刚完成的切换记录覆盖成旧值；失败后需要明确重新应用向量模型配置，不能靠状态同步自动重启旧重建。

重建期间如果又发布了新文档或新版本，整批切换会被拒绝并显示原因。需要重新发起重建，以包含新的发布快照。若已有其他学习任务尚未结束，模型重建会明确拒绝启动，避免与已有任务混用。

旧整库数据集暂时保留，不自动删除，便于核对和恢复。新旧索引并存需要额外存储空间；此改动没有增加生产环境的自动回退或清理按钮。

密钥、接口地址的同步只更新匹配向量空间的连接配置，不会把旧模型记录直接改名为新模型。旧索引继续问答的前提是其对应模型服务仍然可用。

## 部署与历史任务

- 新增数据库迁移 `000057_safe_index_versions`，包含新索引版本、整批构建记录和任务目标数据集字段。由项目原有迁移入口执行。
- API 和 Consumer 必须一起更新；旧 Consumer 不实现新版本保护机制。管理端同步更新模型设置提示文案。
- 此改动保护新发起的学习/重建，不会重新生成此前已被旧实现删除的数据集，也不会自动取消生产队列中的历史积压。
- 没有连接或修改生产环境。不要把本次代码改造视为历史索引已经恢复。

## 本地验证

后端测试使用本地 PostgreSQL 回滚事务，RAG HTTP 测试使用模拟服务，不调用生产或真实模型：

- 处理中旧版本仍能检索，新候选正文不会提前生效。
- 成功后文档、正文和生效指针一起切换，旧版本不再参与新的问答。
- 失败、取消、超时后的成功消息不能切换。
- 重复后台消息不会再次上传已经绑定的候选文档。
- 服务重启后能够恢复候选状态并完成切换。
- 整批部分成功不切换；全部成功才整体切换。
- 整批取消、发布快照变化、向量模型变化时，保留原数据集。
- 模型重建只取已发布快照，忽略待发布草稿。
- 新向量模型和数据集使用独立绑定，不对旧向量模型执行改名或替换。
- 过期的设置保存不会覆盖成功切换后的索引配置基准。

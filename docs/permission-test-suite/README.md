# 文档权限完整测试套件

这套资料用于验证“文档显示权限”和“智能问答权限”是否一致生效。

只把 `import-source/` 压缩后导入系统；不要把本 README、`permission-matrix.csv`、`qa-cases.csv` 导入知识库，否则会污染问答测试结果。

## 一、测试目标

验证以下权限场景：

1. 公开文档：所有人可见、可预览、可下载、可问答。
2. 部门文档：只有指定部门可见、可问答。
3. 指定个人文档：只有指定用户可见、可问答。
4. 等级文档：只有达到最低等级的用户可见、可问答。
5. 父级继承：子文档默认继承父文件夹权限。
6. 子级覆盖：子文档可以覆盖父级权限。
7. 拒绝优先：被拒绝的用户即使属于允许部门，也不能访问和问答。
8. 资源管理器/目录树显示一致：两种视图看到的内容一致。
9. 智能问答不泄露：没有权限时，不能从回答、引用列表、搜索结果中拿到受限内容。

## 二、推荐测试账号

建议创建以下部门、等级、用户。

部门：

- 研发部
- 人力资源部
- 财务部

等级：

- L1 普通员工，rank = 1
- L2 主管，rank = 2
- L3 管理层，rank = 3

用户：

| 用户 | 部门 | 等级 | 用途 |
| --- | --- | --- | --- |
| qa_public | 无或任意部门 | L1 | 普通用户/访客类测试 |
| qa_rd | 研发部 | L1 | 研发部门权限测试 |
| qa_hr | 人力资源部 | L1 | 人力资源部门权限测试 |
| qa_fin | 财务部 | L1 | 财务部门权限测试 |
| qa_boss | 研发部 | L3 | 高等级 + 指定个人测试 |
| qa_rd_blocked | 研发部 | L1 | 拒绝优先测试 |
| qa_level2 | 任意部门 | L2 | 等级权限测试 |

如果当前环境暂时关闭了等级权限，可以先跳过 L2/L3 相关用例；部门、个人、拒绝优先仍然必须测试。

## 三、导入测试文档

已提供可直接导入的压缩包：

- `permission-test-import.zip`

然后在系统中进入目标父目录，执行“批量导入 ZIP”。

如果后续修改了 `import-source/`，建议用下面的方式重新打包，避免中文路径乱码，并避免多出一层 `import-source` 目录：

```bash
cd docs/permission-test-suite
python3 - <<'PY'
from pathlib import Path
from zipfile import ZipFile, ZIP_DEFLATED
root = Path('import-source')
out = Path('permission-test-import.zip')
with ZipFile(out, 'w', ZIP_DEFLATED) as zf:
    for path in sorted(root.rglob('*')):
        rel = path.relative_to(root).as_posix()
        if path.is_dir():
            zf.writestr(rel.rstrip('/') + '/', b'')
        else:
            zf.write(path, rel)
PY
```

导入后应该看到以下一级文件夹：

- 01-公开区
- 02-研发部专区
- 03-人力资源专区
- 04-财务专区
- 05-个人专区
- 06-等级专区
- 07-继承覆盖专区
- 08-拒绝优先专区

## 四、设置权限

导入后按照 `permission-matrix.csv` 设置权限。

建议顺序：

1. 先设置文件夹权限。
2. 再设置需要覆盖父级权限的单篇文档权限。
3. 设置完成后刷新页面，分别在“目录树”和“资源管理器”两个视图确认显示结果。
4. 全部文档执行“发布并学习”。
5. 在“学习进度”中确认成功。

## 五、显示权限验收

每个测试用户登录后检查：

1. 左侧目录树是否只显示有权限的文件夹/文档。
2. 资源管理器视图是否只显示有权限的文件夹/文档。
3. 无权限文档不能通过 URL 直接打开。
4. 无权限文档不能预览。
5. 无权限文档不能下载。
6. 有权限文档可以正常预览和下载。

重点检查：

- `qa_rd` 应能看到研发文档，看不到 HR/财务/个人文档。
- `qa_hr` 应能看到 HR 文档，看不到研发/财务/个人文档。
- `qa_boss` 应能看到指定个人文档和 L3/L2 等级文档。
- `qa_rd_blocked` 即使属于研发部，也不能看到“拒绝优先”文档。
- “07-继承覆盖专区”里，继承父级的文档和覆盖权限的文档显示结果应不同。

## 六、问答权限验收

使用 `qa-cases.csv` 逐条提问。

验收原则：

1. 有权限用户：回答中应该包含对应的唯一答案。
2. 无权限用户：回答中不能包含对应的唯一答案。
3. 无权限用户：引用列表不能出现无权限文档。
4. 无权限用户：即使用非常精确的问题，也不能泄露文档内容。
5. 如果无权限用户没有其他可用文档，允许回答“知识不足”或类似兜底内容。

## 七、发布/学习权限验收

每次改权限后建议执行一次：

1. 修改某个文件夹权限。
2. 确认继承子文档显示结果变化。
3. 对覆盖权限的文档确认不随父级变化。
4. 重新提问受影响的问题。
5. 确认智能问答的引用和回答同步变化。

## 八、常见异常判断

如果“能看到但问不到”：

- 优先看学习进度是否成功。
- 再看 RAG 检索是否有召回。
- 最后看模型是否空回复。

如果“看不到但能问到”：

- 问答权限过滤失效，重点检查 `CanAnswerable` 链路。

如果“看不到但搜索结果出现”：

- 搜索权限过滤失效，重点检查 `CanVisitable` 链路。

如果“目录树看不到，但资源管理器能看到”：

- 前端两种视图使用的节点过滤逻辑不一致。

## 九、节点查阅与文档管理授权验收

节点属性中的“谁可以查阅”和“文档管理权限”独立配置，数据存入 `nodes.permissions`。只有超级管理员（admin）和管理员（manager）可以登录管理后台并管理文档；普通用户的等级、部门、指定用户管理授权，以及历史知识库管理权限，都不能提升其管理资格。已有管理员的全局管理权限继续保留，目录授权不会缩小其权限。

新增“按用户等级”按选中的等级精确匹配；原有“组合授权”中的最低等级仍按 rank 下限匹配。等级查阅用例需先在系统设置启用等级权限。

在测试文件夹 A 中创建直属文档 A1、下级文件夹 B 和下级文档 B1，另建文件夹 C。

| 设置 | 验收结果 |
| --- | --- |
| 查阅授权选 L2 | L2 可以看到并打开文档；未选中的 L1、L3 不能打开 |
| 查阅授权选研发部 | 研发部成员可以查阅，其他部门不可查阅；选择子部门不应授权其兄弟部门 |
| 查阅授权选两名用户 | 两人均可查阅，第三人不可查阅 |
| 管理授权指定用户 | 只能新增管理员账号；历史普通用户授权标记为不生效，保存前需删除 |
| 管理授权选等级 L2 或研发部 | 普通用户即使命中等级或部门，也不能进入后台或管理 A、A1、B、B1、C |
| 管理授权选择任一目录范围 | 默认“当前及下级目录”，可切换为“当前目录”，保存后完整回显；不提升普通用户权限，也不缩小已有管理员全局权限 |
| 普通用户持有历史 full_control/doc_manage 知识库权限 | 仍不能管理文档 |
| 普通用户直接调用管理授权、编辑、删除、上传、发布、批量修改接口 | 全部请求拒绝，不应产生部分修改或自行扩大授权范围 |

保存并刷新后复验。查阅权限修改不应清空管理规则，管理规则修改也不应覆盖查阅权限。

## 十、一级栏目权限验收

一级栏目与文件夹均从“目录权限”进入，使用相同的查阅授权选项和“文档管理权限”弹窗。栏目没有父级继承开关，旧的最低等级规则保留在“公开”或“组合授权”模式中。

1. 一级栏目分别设置“按用户等级”“按部门”“指定用户”，保存后重新打开，配置应完整回显；普通终端用户仍需同时满足栏目和文档的查阅规则。
2. 给一级栏目分配管理授权，默认范围为“当前及下级目录”，可改为“当前目录”；保存后规则完整回显。普通用户即使命中栏目授权仍不能进入后台。
3. 超级管理员和管理员保持已有全局管理权限，不因栏目规则的目录范围缩小权限。
4. 对空栏目分配等级或部门管理授权后，命中规则的普通用户仍不能新建直属文档；只能在用户端按查阅权限浏览。
5. 更新已发布栏目的查阅权限后，用户端列表和正文访问应使用当前规则，避免发布快照中的旧权限继续过滤用户。
6. 栏目查阅权限与管理授权分别保存，互不覆盖；跨知识库的栏目 ID 不应允许读取或修改。
7. 在一级栏目和下级目录中打开“文档管理权限”，修改后取消或点击右上角关闭应返回属性窗口；保存成功后两个窗口均关闭，遮罩消失。重新打开时应回显已保存的规则，不应残留上次未保存的修改。
8. 对栏目直属文档打开属性，父级规则应显示所属栏目的权限；兼容 `parent_id` 为空、栏目 ID 和旧的 `nav:栏目ID`，不能向节点权限接口发送栏目 ID。下级文档仍应读取实际父文件夹的有效权限，目录树与资源管理器结果一致。
9. 文档、目录和一级栏目权限窗口仅展示配置对象、查阅权限和管理权限入口；不展示创建/修改信息，不编辑名称或摘要。保存查阅权限仅调用权限接口，不应调用文档详情更新接口。
10. “跟随上级”显示上级允许查阅的对象；“单独设置”随选择更新对象说明，组合授权应说明部门/用户为任一匹配，并且仍需满足等级要求。批量继承应说明各节点跟随各自上级，不显示第一个节点的规则代表全部节点；内容较多时窗口内容可滚动，取消和保存按钮始终可用。

可用 `PANDA_WIKI_TEST_PG_DSN` 启用 `TestNavigationManagementPostgresRoundTrip`，测试在事务中创建临时数据，并在结束时全部回滚。

## 十一、管理员后台准入验收

1. 超级管理员和管理员以正确密码登录 admin 端成功；普通用户以正确密码登录得到 HTTP 403 和“仅管理员可登录管理后台”提示，不计为密码错误。
2. 所有角色使用错误密码均返回通用用户名或密码错误，不颁发 Token。
3. 普通用户在用户端通过 `/share/v1/auth/login/account` 登录成功，通过 `/share/v1/auth/user` 获取本人信息，原有等级、部门、指定用户查阅权限仍有效。
4. 普通用户已有的 JWT 和 API Token 直接访问 `/api/v1`、`/api/pro/v1` 管理接口均被拒绝；前端清除旧后台登录状态并返回登录页。
5. 管理员降级为普通用户后，其旧 JWT 和已进入 Redis 缓存的 API Token 在下一次管理请求中立即被拒绝；用户端查阅身份仍可使用。
6. 等级、部门和指定用户授权不能绕过角色限制；未知角色、已删除账号同样不能访问管理后台。

数据库回归测试在事务中创建临时账号并全部回滚；设置 `PANDA_WIKI_TEST_REDIS_ADDR` 可同时验证缓存 API Token 和账号降级场景：

```bash
cd backend
PANDA_WIKI_TEST_PG_DSN='本地测试库 DSN' PANDA_WIKI_TEST_REDIS_ADDR='本地 Redis 地址' \
  go test ./usecase ./middleware ./repo/pg -run 'TestAdministrator(Login|Access)Postgres|TestNavigationManagementPostgresRoundTrip' -v
```

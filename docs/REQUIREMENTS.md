# AI知识库产品说明文档

## 1. 文档定位

本文档用于说明 AI知识库 当前版本的产品能力、使用对象、页面结构、功能模块和使用规则，重点回答以下问题：

1. AI知识库 是什么
2. 这个系统给谁用
3. 当前系统有哪些页面和功能
4. 用户如何使用这些功能
5. 系统在产品层面有哪些规则、边界和限制


## 2. 产品概述

AI知识库 是一个 AI 驱动的知识库系统，用于帮助组织或个人搭建自己的文档站点、知识中心和问答入口。

AI知识库 由两部分组成：

1. **管理后台**
   用于知识库维护、文档编辑、配置管理、发布和运营
2. **用户前台**
   用于文档浏览、搜索、问答和公开访问

AI知识库 不只是一个“放文档的站点”，而是一套完整的知识产品，具备以下能力：

- 文档内容管理
- 知识结构组织
- 文档发布与访问
- AI 问答
- 检索增强
- 富文本与 Markdown 内容支持
- 知识库的配置能力

---

## 3. 产品目标

AI知识库 当前版本的核心目标是：

1. 让管理员可以搭建和维护知识库
2. 让编辑者可以高效编写和更新文档
3. 让普通用户可以顺畅浏览文档并进行 AI 问答
4. 让知识内容不仅能“被看到”，还能“被检索、被理解、被回答”

产品价值体现在三个层面：

- **对组织**：沉淀知识、统一入口、提升复用效率
- **对管理员**：降低配置和维护成本
- **对读者**：更快找到答案，而不是只看到一堆文档

---

## 4. 用户角色

## 4.1 系统管理员 / 知识库管理员

这类用户主要使用管理后台。

主要职责：

- 维护知识库内容和目录结构
- 管理站点设置
- 管理模型、机器人、发布、统计和对话相关功能

核心关注点：

- 后台是否易于管理
- 文档编辑是否稳定
- 发布和配置是否可控

## 4.2 编辑者

这类用户主要使用文档编辑器。

主要职责：

- 创建和编辑文档
- 维护文档内容格式
- 更新标题、摘要、正文、图片、附件等信息

核心关注点：

- 编辑体验是否稳定
- 富文本和 Markdown 是否都可用
- 保存是否可靠

## 4.3 普通读者 / 业务用户

这类用户主要使用用户前台。

主要职责：

- 浏览知识库内容
- 搜索资料
- 通过 AI 问答获取答案

核心关注点：

- 页面是否容易理解
- 文档是否容易找到
- AI 回答是否有帮助

---

## 5. 产品结构

AI知识库 当前产品结构分为两个入口。

## 5.1 管理后台

管理后台面向知识库维护人员，承担“管理”和“生产”职责。

主要入口页面包括：

- `/login`
- `/`
- `/setting`
- `/release`
- `/stat`
- `/conversation`
- `/doc/editor/:id`
- `/doc/editor/history/:id`
- `/doc/editor/space`

## 5.2 用户前台

用户前台面向最终读者，承担“浏览”和“问答”职责。

主要入口页面包括：

- `/auth/login`
- `/home`
- `/welcome`
- `/node`
- `/h5-chat`
- `/widget`
- `/feedback`

---

## 6. 管理后台说明

管理后台是 AI知识库 的核心操作端，用于维护知识内容和系统配置。

## 6.1 登录

入口：

- `/login`

功能说明：

- 用户输入账号和密码登录后台
- 登录成功后进入主控制台
- 未登录访问受保护页面时会被重定向到登录页

产品规则：

- 登录态基于 token 保持
- 鉴权失败时会清除登录态并跳回登录页

如何操作：

1. 打开后台登录页
2. 输入账号和密码
3. 提交登录
4. 登录成功后进入后台主界面

## 6.2 文档管理首页

入口：

- `/`

功能说明：

- 展示当前知识库的文档结构
- 支持目录和文档节点管理
- 支持树形浏览和拖拽排序
- 支持从目录中快速进入编辑页

用户可在该页面完成的典型操作：

- 浏览目录结构
- 新建文档
- 调整节点位置
- 打开指定文档编辑

产品价值：

- 这是知识库维护的主工作台
- 文档组织效率直接决定整个知识库的维护效率

如何操作：

1. 进入后台首页
2. 在左侧或主区域查看当前知识库目录
3. 选择已有目录或文档节点
4. 根据页面操作入口新建文档、调整位置或打开编辑页
5. 如需改变层级或顺序，可通过拖拽完成调整

## 6.3 文档编辑器

入口：

- `/doc/editor/:id`

这是后台最核心的页面之一。

支持的内容类型：

- 富文本
- Markdown

编辑器当前覆盖的核心能力：

- 编辑标题和正文
- 保存文档
- 查看目录大纲
- 统计字符数
- 管理摘要
- 上传图片或附件
- 导出内容
- 切换文档内容类型
- 查看历史版本入口

对于富文本编辑：

- 支持常见格式化能力
- 支持图片、代码块、表格、标题等结构化内容
- 支持实时协同编辑能力

对于 Markdown 编辑：

- 支持 Markdown 内容维护
- 支持 Markdown 内容展示
- 可用于需要源码式编辑的场景

产品规则：

- 编辑页是高频使用页面，稳定性优先级最高
- 保存状态、协同状态、内容是否修改，需要明确反馈给用户
- 协同能力不能导致编辑页无法打开

如何操作：

1. 从文档管理首页打开目标文档
2. 在编辑器中修改标题和正文
3. 根据需要插入图片、附件、代码块、表格等内容
4. 查看左侧或右侧目录大纲，快速定位内容位置
5. 完成编辑后执行保存
6. 如需查看历史版本，进入历史版本页
7. 如需切换内容类型，可在编辑器提供的相关入口中切换富文本或 Markdown

## 6.4 历史版本

入口：

- `/doc/editor/history/:id`

功能说明：

- 查看当前文档的历史版本记录
- 对指定历史版本进行查看和恢复

使用价值：

- 为内容误改、回滚和版本追溯提供保障

如何操作：

1. 在编辑页进入历史版本入口
2. 查看版本列表
3. 选择某个历史版本查看详细内容
4. 如确认需要回退，执行恢复操作

## 6.5 空间页

入口：

- `/doc/editor/space`

功能说明：

- 作为文档工作区的辅助页面
- 用于知识库上下文和编辑工作空间切换

## 6.6 系统设置

入口：

- `/setting`

功能说明：

- 管理站点与知识库相关配置
- 管理模型、机器人、SEO、展示和组件相关设置
- 管理 Web 端呈现和外部接入能力

该模块的本质角色是：

- AI知识库 的“产品配置中心”

常见使用场景：

- 调整站点展示配置
- 配置问答相关模型
- 配置机器人接入
- 调整页面模块与展示逻辑

如何操作：

1. 进入设置页
2. 根据设置分组选择目标配置项
3. 修改参数内容
4. 提交保存
5. 返回前台或相关页面验证效果

## 6.7 发布管理

入口：

- `/release`

功能说明：

- 管理知识内容的发布流程
- 查看和处理版本发布相关内容

产品目标：

- 区分内容编辑态和对外呈现态
- 让管理员可以控制内容上线节奏

如何操作：

1. 进入发布管理页
2. 查看当前可发布内容或历史发布记录
3. 选择需要发布的内容版本
4. 执行发布或相关版本操作
5. 到前台验证发布结果

## 6.8 数据统计

入口：

- `/stat`

功能说明：

- 查看访问、来源、热门内容等统计数据
- 支持从内容维度和流量维度理解站点使用情况

产品价值：

- 帮助管理员知道哪些内容被访问、哪些内容更有价值

如何操作：

1. 进入统计页
2. 查看访问总量、热门页面、来源分布等内容
3. 根据统计结果判断哪些内容需要优化或补充

## 6.9 对话管理

入口：

- `/conversation`

功能说明：

- 查看问答相关数据
- 查看对话详情和消息内容

产品价值：

- 帮助管理员理解用户真实在问什么
- 为优化知识内容和问答质量提供依据

如何操作：

1. 进入对话管理页
2. 查看会话列表
3. 打开某条会话查看详细问答内容
4. 根据用户提问优化文档或问答配置

## 7. 用户前台说明

用户前台是知识库面向读者的访问端，用于阅读内容和进行问答。

## 7.1 登录

入口：

- `/auth/login`

功能说明：

- 用户登录前台系统
- 登录后可访问受保护内容

如何操作：

1. 打开前台登录页
2. 输入账号和密码
3. 登录成功后进入首页或默认访问页

## 7.2 首页 / 欢迎页

入口：

- `/home`
- `/welcome`

功能说明：

- 作为站点入口页
- 展示知识库首页内容、导航或欢迎信息

产品目标：

- 让用户快速理解当前站点是什么
- 提供进入知识内容和问答能力的入口

如何操作：

1. 打开首页或欢迎页
2. 浏览页面提供的导航入口或推荐内容
3. 进入具体文档或问答页面

## 7.3 文档查看页

入口：

- `/node`

功能说明：

- 展示文档详情内容
- 支持目录导航和阅读
- 支持 Markdown 丰富渲染
- 支持图片、代码块、数学公式、Mermaid 等展示

这是普通读者最核心的页面。

产品目标：

- 让文档内容可读、可查、可理解

如何操作：

1. 通过导航或搜索进入目标文档
2. 阅读正文内容
3. 使用目录大纲快速定位章节
4. 如需进一步理解内容，可继续发起问答

## 7.4 AI 问答

入口：

- 页面内问答能力
- `/h5-chat`
- `/widget`

功能说明：

- 用户围绕知识库发起问题
- 系统结合知识内容生成回答
- 支持流式回答
- 支持反馈和部分上下文能力

问答入口分为几种形态：

1. 站点内部问答
2. 移动端聊天页
3. 可嵌入的 Widget 问答组件

产品目标：

- 将“阅读文档”升级为“直接获得答案”

如何操作：

1. 在前台页面找到问答入口
2. 输入问题
3. 等待系统返回流式回答
4. 如结果不理想，可继续追问或更换表达方式
5. 如页面支持反馈，可对回答结果进行反馈

## 7.5 反馈

入口：

- `/feedback`

功能说明：

- 用户提交反馈信息
- 用于收集站点或问答体验问题

如何操作：

1. 进入反馈页
2. 填写反馈内容
3. 提交反馈

## 8. 核心功能说明

本节从产品功能角度，对 AI知识库 当前主要能力进行统一说明。

## 8.1 知识库与导航管理

系统支持知识库内容以目录和节点形式组织。

主要能力：

- 知识库内容分层组织
- 目录导航
- 节点移动与排序
- 知识结构可视化管理

设计目的：

- 让大量文档可以被持续管理，而不是堆积成平铺内容

操作说明：

1. 管理员在后台首页维护目录结构
2. 将文档放入对应目录
3. 通过拖拽调整显示顺序和层级

## 8.2 文档编辑

系统支持两类主要文档编辑形态：

- 富文本编辑
- Markdown 编辑

主要能力：

- 标题和正文维护
- 内容保存
- 格式编辑
- 图片/附件上传
- 摘要维护
- 导出

设计目的：

- 满足不同类型内容生产习惯
- 兼顾结构化编辑和源码式编辑

操作说明：

1. 打开文档编辑器
2. 选择适合当前文档的内容形式
3. 编辑完成后保存
4. 需要回溯时进入历史版本页

## 8.3 文档阅读

系统支持最终用户查看文档内容。

主要能力：

- 文档正文渲染
- 大纲导航
- 丰富内容展示
- 评论、反馈或扩展入口（视配置而定）

设计目的：

- 让知识内容在前台真正可用，而不是仅存在后台

操作说明：

1. 用户从首页、导航或搜索进入文档
2. 在文档页阅读正文和结构内容
3. 配合问答能力理解复杂内容

## 8.4 AI 问答

系统支持围绕知识库内容进行 AI 问答。

主要能力：

- 基于知识库回答问题
- 流式返回结果
- 历史对话查询
- 反馈问答结果

设计目的：

- 缩短“找到答案”的路径
- 提高知识库使用效率

操作说明：

1. 用户输入问题
2. 系统基于知识库内容返回答案
3. 用户继续追问、阅读文档或反馈结果

## 8.5 协同编辑

系统当前支持富文本文档的协同编辑能力。

主要能力：

- 多人进入同一文档进行编辑
- 实时同步内容变更
- 展示协同连接状态

产品要求：

- 协同能力不能破坏编辑器基础可用性
- 当协同条件不满足时，系统应能清晰提示或降级

操作说明：

1. 多个用户进入同一富文本文档
2. 各自进行编辑
3. 观察页面显示的协同连接状态
4. 如协同不可用，按页面提示切回普通编辑或稍后重试

## 8.6 发布与版本

系统支持对知识内容进行版本和发布管理。

主要能力：

- 查看版本记录
- 回退历史版本
- 管理发布相关内容

设计目的：

- 提供可追踪、可恢复、可控制的内容生命周期

操作说明：

1. 文档编辑完成后保存
2. 在版本或发布相关页面查看当前状态
3. 根据需要执行发布或版本恢复

## 8.7 统计与对话运营

系统支持对内容使用情况和问答使用情况进行运营观察。

主要能力：

- 热门内容统计
- 访问来源分析
- 问答会话查看
- 对话内容分析

设计目的：

- 让管理员不是只“发布内容”，而是能持续优化内容

操作说明：

1. 查看统计页了解访问情况
2. 查看对话页了解用户提问
3. 反向优化文档内容、导航结构和问答配置

## 9. 关键产品规则

## 9.1 后台与前台分工明确

管理后台负责：

- 内容生产
- 内容管理
- 配置管理
- 统计与运营管理

用户前台负责：

- 内容消费
- 内容浏览
- 问答交互

## 9.2 文档是系统核心对象

无论是后台管理、前台阅读、AI 问答还是版本管理，核心都围绕文档节点展开。

这意味着：

- 文档结构设计是产品核心
- 编辑器稳定性是产品核心
- 文档详情页和问答页是用户最关键的使用场景

## 9.3 协同能力服从可用性

协同编辑是增强能力，不应凌驾于编辑器基础可用性之上。

产品要求：

- 页面必须能打开
- 内容必须能编辑和保存
- 协同异常不能直接导致编辑页崩溃

## 9.4 AI 能力服从知识库内容

AI知识库 的 AI 问答不是通用聊天产品，而是服务于知识库内容的问答系统。

因此：

- 问答质量依赖知识内容质量
- 检索和索引质量会直接影响回答效果
- 问答是知识库能力的延伸，而不是独立模块

## 10. 典型使用流程

## 10.1 管理员日常维护流程

1. 登录后台
2. 进入文档管理首页
3. 创建或选择文档
4. 进入编辑器维护内容
5. 保存并查看版本或发布信息
6. 在设置页调整相关配置
7. 在统计和对话页观察使用效果

## 10.2 普通用户使用流程

1. 打开前台站点
2. 进入首页或欢迎页
3. 浏览导航并打开文档
4. 阅读文档内容
5. 通过搜索或问答获取答案
6. 提交反馈或继续浏览

## 11. 已知产品边界

本文档描述的是当前项目主产品，而不是未来扩展蓝图。

当前产品边界包括：

- 主体形态为 Web 管理后台 + Web 用户前台
- 富文本和 Markdown 是当前主要内容形态
- AI 问答围绕知识库内容展开
- 协同编辑属于已有能力，但其稳定性需要持续维护

本文档不覆盖：

- 未来桌面端详细方案
- 未来移动端详细方案
- 纯技术实现细节

---

## 12. 成功标准

从产品角度，当前 AI知识库 的成功标准可以概括为：

1. 管理员能顺畅维护知识内容和配置

# 智能问答诊断日志

管理端的“问答记录”详情会显示每轮对话的诊断过程。日志与原会话按知识库和会话关联，并复用会话详情接口现有的知识库数据操作权限。

诊断步骤覆盖问题接收、模型配置读取、问题过滤、历史消息与提示词读取、用户等级和访问权限加载、RAGLite 向量检索、检索结果对应到文档、文档权限筛选、最终模型上下文、模型生成、回答保存和用量更新。每步记录状态、开始和结束时间、耗时；失败步骤会记录错误原因。检索日志会保存发送给 RAGLite 的查询、改写后的查询和返回片段；权限筛选会列出允许或排除的文档及原因；模型输入日志展示实际送入模型的消息。

RAGLite 当前的检索接口只返回片段，不返回每个片段的相似度分数，也不暴露向量化和内部排序各自的耗时。因此日志能指出 RAGLite 请求整体耗时、查询内容和结果，不能进一步判断它内部的具体子步骤。

日志包含用户标识、用户问题、检索片段、模型上下文和回答内容，默认保留 30 天，由 Consumer 的每日定时任务删除。为限制单条日志大小，每个文本最多保存 2,400 个字符，每个列表最多保存 50 项；发生截断时会在诊断数据中标注。模型密钥不会写入诊断日志。

会话创建并通过 nonce 校验后，系统从收到问题开始记录，包括保存用户问题这一步；之后模型配置或问答流程失败，也会保存失败日志。应用初始化、会话创建或 nonce 校验失败发生在诊断记录建立之前，这些情况继续通过服务端应用日志排查。

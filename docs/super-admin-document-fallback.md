# 超级管理员文档权限兜底

数据库角色为 `admin` 的超级管理员始终可以查阅、管理所有文档，无需单独配置目录授权。
角色为 `manager` 的普通管理员和角色为 `user` 的普通用户继续按现有权限规则判断。
判断依据是数据库当前角色，不是账号名、前端传参或登录时写入的角色快照。

- 查阅兜底优先于栏目、全部父目录、文档自身的部门、等级、白名单和排除规则。
- 用户端目录、文档正文、原文件/预览文件下载、智能问答和引用检查共用服务端查阅判断。
- 管理端沿用超级管理员全局管理规则。超级管理员天然处于所有父目录的管理范围内。
- 查阅对象预览名单同步包含超级管理员；权限弹窗说明这条例外。
- 不修改已保存的文档权限，不给其他账号追加授权，不新增数据库迁移。
- 账号降级后，下一次请求重新读取数据库角色，取消全局兜底。

用户端仍需登录。管理端和用户端保持独立会话；从管理端打开链接不会自动切换用户端账号。
用户端登录普通账号时，仍以该普通账号的查阅权限为准。
原有文档存在性、发布状态、所属知识库和文件与文档的绑定校验继续执行。

部署需更新 API；使用现有部署脚本可执行 `bash deploy/server/deploy.sh upgrade backend`。
管理端权限说明的展示更新需同时执行 `bash deploy/server/deploy.sh upgrade admin`。

验证覆盖：

- `TestSuperAdminDocumentFallbackPrecedesEveryReadingConstraint`：祖先、部门、等级、个人白名单和排除规则；等级功能开/关；匿名身份和客户端 JSON 不可获得兜底。
- `TestSuperAdminDocumentFallbackPostgres`：使用本地 PostgreSQL 回滚事务，核对正文/下载校验、目录展示、问答筛选、全局管理和账号降级。
- `TestSuperAdminIsAlreadyWithinEveryManagementParentScope`：超级管理员全局管理与普通管理员的父级委派范围。
- 既有查阅名单、权限计算、目录查询、处理器和认证中间件回归测试。

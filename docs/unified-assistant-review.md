## 必须补齐（9 项 P1）

### R01：私有产物与既有会话详情、续聊和复制路径没有隔离协议

方案要求文件默认仅本人可用（方案第 137、155 行），但既有用户端会话详情仅传入 KB 和会话 ID，没有把访问者传入查询；既有 resume 路径对非本人且无有效 nonce 的访问直接复制历史。

证据：

- `backend/handler/share/coversation.go:111`
- `backend/repo/pg/conversation.go:74`
- `backend/usecase/conversation.go:189`
- `backend/repo/pg/conversation.go:180`

若直接把新文件、任务、内容规范和来源添加进旧历史响应或复制逻辑，可能暴露他人产物信息或错误转移所有权。这是静态可见的旧行为与新私有要求不兼容，不是已完成的新接口漏洞验证。

修订：详情、恢复、续聊、任务读取、修订、取消、重试、预览和下载统一执行账号归属策略。首版文件保持私有，共享历史不授予文件和任务访问权，也不能通过 fork 转移所有权；没有明确分享授权时，不能仅凭会话 ID 自动读取或复制受限历史。旧会话开放行为应先完成专门回归与修正。

验收：账号 B 获取 A 的会话/run/artifact ID，仍不能读取私有卡片、来源、内容规范或取消/重试；分享和 fork 不改变结果。

### R02：来源必须在历史和文件修订间传递，不能只记录本轮新引用

方案第 30、156、157 行尚未定义来源传递的闭包。现有问答把历史助手和用户文本直接带入新模型上下文（`backend/usecase/llm.go:109`、`:224`）。

场景：首轮基于机密 A 生成正文，撤销 A 权限后要求“以上生成 Word”或“只改封面”。本轮即使没重新检索 A，旧正文仍含 A；若只登记本轮引用，下载检查也可能错误放行。

修订：服务端按实际模型输入、历史消息和基础产物，保守继承全部内部来源及版本，再合并新来源；不能由模型选择哪些来源需要权限检查。所有恢复检查点、生成和发布前重新校验。失权后不能仅删除引用而保留正文继续生成。旧内容无可靠来源时重新取材，不直接复用。

验收：撤权后，从历史文本、旧产物、旧检查点和 fork 历史均不能绕过限制生成或下载。

### R03：公网关键词生成需要独立的输入边界

方案第 91～95 行是合理原则，但当前历史中含有内部内容；若搜索词规划器复用整段会话，仍可能泄露项目代号、客户或参数。发送后展示关键词不能阻止泄露。

修订：公网搜索词规划不得自动接收知识正文、旧回答和文件内容规范，只接收本轮明确的公开搜索请求及经批准的公开上下文。指代不明时使用公开关键词，或在发送前让用户确认具体检索词。服务端执行器强制校验开关、资料策略和搜索参数；不能只依赖提示词。保留管理员禁用公网出口的能力。

验收：先讨论内部客户，再问“联网找同类案例”，捕获的搜索请求中不得出现未批准的内部客户、项目代号和正文片段。

### R04：文件任务进入队列太晚，取材时刷新仍可能中断

方案图在检索、联网、内容生成之后才入队（第 38～45 行），与第 32 行“刷新不取消文件任务”不完全一致。既有 Chat 复用 HTTP 请求上下文（`backend/handler/share/chat.go:101`、`:114`）。

修订：认证及轻量参数校验后，先持久化可恢复 run 并返回稳定 ID；意图规划、取材、联网、内容生成、渲染均属于后台执行生命周期。SSE 订阅状态，不拥有 run。无法立即判定意图时也先记录通用 run，随后转文件任务。

验收：取材阶段刷新、API 重启、内容生成阶段关闭浏览器，都能找回同一任务；不只测试渲染阶段断开。

### R05：幂等、租约与取消需要可执行协议

方案第 123、133 行只列名词；消息请求没有客户端请求 ID（第 139 行）。既有 Producer 未使用 key 做去重（`backend/mq/nats/producer.go:115`），Consumer 的 Background context 和 NATS 心跳不检查业务租约（`backend/mq/nats/consumer.go:108`、`:142`），不能原样复用作为完整保障。

修订：

- 增加稳定 `client_request_id`，数据库唯一约束覆盖账号、KB 和请求 ID；同键不同请求体拒绝，同键重发返回原 run。
- 用户消息、助手占位、run 和待投递状态同事务建立；调度器持续重试未投递记录，允许安全重复投递。
- Worker 原子认领并递增 lease epoch；心跳、阶段保存与最终发布均检查 epoch，失租 Worker 不得提交迟到结果。
- 取消与完成通过数据库条件更新竞争，取消成功后不能再次变完成。
- 明确 ACK、退避、最大尝试、消息保留与数据库补偿扫描；NATS 消息去重只作优化，不替代数据库幂等。

验收：双击/超时重发只产生一个逻辑任务；模拟 A 失租、B 接管、A 恢复，以及取消与完成并发，均不能重复版本或复活取消任务。

### R06：OSS 与 PostgreSQL 不能依靠一个事务保证一致

方案第 127 行的表述不够准确，OSS 上传不参加 PostgreSQL 事务。文件完成、预览完成、回收之间也缺少发布协议。

修订：每个 attempt 使用隔离且不可变的对象键；上传并核对大小/hash 后，凭有效租约在数据库发布 ready 指针。保存上传检查点，恢复时可找回同一 attempt 对象。原文件与预览分别保存状态，预览失败不抹去已成功原文件。GC 只处理超过宽限期、没有有效引用且没有活跃租约的对象；旧 attempt 不能清理新 attempt 文件。

验收：上传成功但数据库提交前宕机、数据库提交后预览失败、失租 Worker 迟到清理，均不会出现 ready 文件被误删。

### R07：后台生成不能占住整个聊天输入状态

方案第 22、32 行未明确任务接受后本轮消息何时结束。现有主问答组件以一个 loading 状态阻止再次发送，卸载和切历史会取消 SSE（`web/app/src/components/QaModal/AiQaContent.tsx:411`、`:518`、`:532`）。

修订：run 持久化并返回 ID 后结束本轮发送状态，恢复输入；任务卡片独立订阅。首版建议每会话同时一个文件生成任务，其间可继续普通问答；未完成产物的修订提示等待完成或取消重建。关闭、切会话只停止展示订阅，取消 run 使用独立操作。

验收：生成中继续提问、切到另一个会话再回来，输入可用且原任务状态正确。

### R08：“第三页”必须按文件类型定义

方案第 30、180 行统一承诺按“第三页”修改。PPT 有幻灯片，Excel 有工作表和单元格，但 Word 排版页码依字体、纸张和渲染器变化，仅保存结构化内容不足以准确定位。

修订：PPT 按稳定 slide ID 和当前版本页序；Excel 按 sheet ID、列名和单元格范围；Word 首版按章节或段落。若确实支持 Word 页码，必须明确以系统 PDF 预览为准，并建设页码到内容块的映射。目标歧义时让用户选择，不能错误修改后宣称理解正确。

验收：修订针对明确的基础版本与结构对象；Word 页码跨 Office/WPS 不承诺天然一致。

### R09：定义文件交付的质量门槛

方案第 109、113、183 行没有明确自动/人工检查的边界，公式白名单也未实际列出。

修订：增加质量矩阵：

- Word/PPT：结构可重读、所需字体已安装、页/幻灯片清单一致、PPT 元素不越界；每套模板以中文长文本、长表格和缺图样本做视觉验收。不能把 PDF 转换成功当成内容或排版完全正确。
- Excel：写明支持公式及范围、空值/除零处理、数值与缓存结果样本；不支持公式明确拒绝。
- 状态分开：结构及内容校验失败不可下载；文件校验通过但仅预览转换失败，建议允许下载并提示。

验收软件需指定实际使用的 Office/WPS 版本与操作系统，不承诺所有版本排版完全一致。

## 实施细则建议（7 项 P2）

### R10：冻结每轮资料范围

提交时将“当前文档”解析成固定节点和版本 ID，将目录枚举结果及范围存到 run。卡片展示实际范围；切换网页和恢复会话不静默改变已提交任务。修订默认继承目标版本资料，扩展来源有明确记录。（方案第 12、74、139 行）

### R11：列出用户端入口矩阵

普通问答弹窗、Widget、独立 H5/微信页分别定义可发起生成、可读文件卡片、可下载、保持旧行为。共享消息解析和卡片组件，避免历史在另一个入口丢失产物。（方案第 16、139 行）

### R12：区分文件修订与执行尝试

定义 family、revision、attempt；渲染重试属于同一用户可见 revision，用户修改或重新生成才产生新 revision。明确 base_artifact_id，同一基础版本的并发修订需选择分支或冲突检测，不能隐式采用“最新文件”。（方案第 30、127、133、147 行）

### R13：细化滚动升级和回滚

采用扩展式迁移；先建立兼容表结构，再启动匹配 Worker，通过功能开关开放。升级停止认领并妥善释放/排空租约。原部署脚本按数组枚举服务，需同步补齐服务组、健康检查、回滚镜像、日志及开发启动/停止脚本；旧 Worker 不能消费不兼容的新任务。（`deploy/server/deploy.sh:41`、`:506`、`:517`）

### R14：DNS 校验必须绑定实际拨号

公网抓取不能只先校验域名、后让普通客户端再次解析。需校验实际连接 IP，逐次验证重定向，覆盖 IPv6、映射地址和代理路径；TLS 证书正常验证。不要直接复用当前文件 URL 下载客户端作为公网搜索读取器：其 TLS 配置有 `InsecureSkipVerify`，URL 验证与连接也是分离的（`backend/usecase/file.go:67`、`:498`；`backend/utils/ip_addr.go:175`）。这里是新抓取器的设计要求，未做现有入口攻击实测。

### R15：检查 Office 包中的活动内容和外部关系

图片经受控读取后内嵌，不把任意路径/URL交给生成器；禁止宏、OLE、外部模板、外部工作簿和自动更新链接。允许普通来源超链接，但需限定协议。验证 OOXML 关系后再交预览，避免转换器或 Office 打开时自动外发。（方案第 99、109、113 行）

### R16：增加端到端预算，不只限制文件页数

独立 Worker 只能隔离消费池，不能天然隔离共用模型服务、数据库、OSS和宿主机 CPU。补用户级/全局并发、排队长度、单任务 token/耗时/重试预算和资源限制；生成限流时不能拖垮普通问答。初始规模上限不是容量证明。

Excel 大批量数据应由程序从授权原表读取和处理，模型负责字段映射和解释，不能承诺让模型逐单元格可靠生成 5000 行数据。需要覆盖超大目录、长历史和多用户同时生成的容量样本。（方案第 83、117、121、186 行）

## 待用户决定（不把全部选择变成开工阻塞）

1. 是否三种格式同批对用户开放：建议同一项目按阶段验证，第一版模板范围固定。
2. 文件保存期限：当前 30 天只是建议，需要明确提示用户；可改为更长或由用户手动删除。
3. 实际验收的 Office/WPS 软件环境及企业模板；无企业模板时使用通用模板。
4. 搜索服务、访问条件和凭据；未配置前关闭入口，真正联网能力必须实联调。

预览失败是否允许下载也应在修订稿明确，团队建议“结构/权限验证通过可下载，清楚提示预览失败”。

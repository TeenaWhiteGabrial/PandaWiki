> 2026-10-26 补充修复已完成：两端 HttpOnly 会话、普通文档私有上传策略、服务指纹头过滤、Gotenberg 转换及 NATS 监控认证。详见[安全补充修复与部署说明](安全补充修复-20261026.md)。原报告本地已修复跟踪项现为 **33 项**；本文较早表格/说明保留历史口径，最新逐项状态见 JSON 与补充说明，生产仍未验证。

2026-10-26，按用户确认将系统定位为内部知识库。未连接生产，没有调整任何现有栏目或文档授权，也没有访问或修改外部 OSS 的 ACL。

## 当前规则

- 未登录：不能访问目录、正文、预览/下载签发、搜索、网页及嵌入式问答、历史会话；文档页面跳转登录页并保留原路径。
- 已登录：继续按栏目、祖先目录、文档的部门、等级、个人授权与排除规则检查；普通管理员在用户端没有额外全局可读资格。
- 全员可查阅：所有已登录用户可查阅，不包括游客。管理端标签、权限说明与公开确认提示均已明确需登录。
- 登录页面及其品牌信息、账号登录和验证码仍可访问，避免登录循环。
- 有效 API 密钥仍作为接口身份凭据使用；OpenAI 兼容接入继续核验独立配置的密钥，缺少凭据直接返回 401，不改变既有密钥协议。

## 实现

- 后端分享鉴权取消匿名/旧共享口令的放行分支。缺少有效凭据返回 HTTP 401、业务码 40101，身份相关响应使用 private/no-store。
- Widget 问答、搜索和反馈补上分享鉴权；检索使用服务端解析出的用户身份，覆盖请求正文自填的用户 ID。
- Next 页面代理实际调用后端身份接口校验会话，不仅检查 Cookie 是否存在；伪造、已撤销和服务端已过期会话无法打开页面。身份服务不可用时返回 503，不放行，也不误删有效登录。
- 本站原始文件代理加入登录检查。通过 Next 转发的请求可从登录 Cookie 恢复 Authorization；前端也能识别仅 Cookie 存在的登录态，减少服务端/客户端身份不一致。
- 历史查阅资料补充“未登录全部拒绝”的基线；旧匿名公开模式记录保留为历史证据。

## 部署与边界

本地 API 已重启，前端开发服务已加载新代码。正式环境需要更新 API、用户端及管理端；本次没有代为正式部署。

本次保护的是系统页面和接口。已经发出的 OSS 签名地址在自身有效期内仍是独立访问凭据；如果 OSS 或历史 MinIO 对象本身允许公共读，绕过本站直接访问源站仍可能成功。那属于原文件存储权限待核实项，不能把此次强制登录当作已修改源站 ACL 或撤销历史直链。

## 登录态与兼容性

- 管理端使用 `pw_admin_session`，用户端使用 `pw_reader_session`；均为 host-only、Path=/、HttpOnly、SameSite=Strict。不同入口不会拿另一种 Cookie 自动代替当前身份。
- HTTPS 请求或可信网关转发 `X-Forwarded-Proto: https` 时设置 Secure。也可在生产 `.env` 设置 `AUTH_COOKIE_SECURE=true` 强制 Secure。当前 HTTP 环境为保持可登录不会强制 Secure，**HTTP 明文传输问题仍须 HTTPS 部署解决**。网关应覆盖客户端传入的转发协议头。
- 登录和使用 Cookie 身份的写操作要求 `X-PW-CSRF: 1`，同时校验请求 Origin，并拒绝跨站请求；两端普通请求、流式问答及服务端渲染内部请求已适配。浏览器表单无法自行添加该请求头，不依赖仅前端检查。
- 前端不再检查 localStorage 是否有令牌来判断已登录，而是向后端恢复并验证身份。后端仅提供不含凭据的会话到期时间，用于保留用户名/内容到期自动清理；页面从后台回到前台时另行核验会话，不用定时轮询延长闲置会话。登录失效由服务端返回业务码 40101，普通文档无权限仍不触发退出。
- 退出、本人改密、无效会话均由服务端删除 HttpOnly Cookie；同时发送 Max-Age=0 和过去的 Expires，兼容 Next.js 代理的 Cookie 序列化。
- 旧的可读 Cookie/localStorage 令牌不会迁移进新 Cookie；升级后浏览器需要重新登录。有效 API 密钥和显式 Bearer 接口凭据仍走原鉴权协议。程序化账号登录改为使用 Cookie Jar 并发送 CSRF 请求头，不再从登录 JSON 提取 token。
- 本次没有新增数据库迁移，仍依赖此前会话迁移 56。不同版本的前后端认证方式不能混用，必须一起升级。

## 私有文件和展示图片

普通文档上传由存储封装统一覆盖 ACL，调用方自带的 public-read/grant 不能扩大普通文档对象权限；服务端不会在私有上传失败后自动退回公共读。ZIP 直传返回必须携带的 `headers`，ACL 也绑定进签名；现有分片上传在初始化时设置私有权限。

MinIO 不支持用对象 ACL 覆盖公共桶策略，因此先检查桶策略；发现匿名 GetObject 授权时拒绝新文档写入，不擅自修改桶策略或旧文件。检查采取保守拒绝方式，可能要求运维为文档提供独立私有桶。已签发 URL 仍按自身有效期生效。

登录页 Logo 等展示图片必须在登录前加载，因此图片专用上传保留原存储 ACL 行为，不主动添加 public-read；图片仍须通过实际解码检查，使用独立 `assets/` 前缀。**图片专用入口不应承载机密文档图片**；普通文档入口上传的 JPG/PNG 仍按私有文档处理。已有图片链接和历史文件没有批量重写。

## 内部服务与部署

| 服务 | 部署变化 |
| --- | --- |
| admin | 增加静态 Go 响应过滤代理，外部仍访问原 80 端口；Nginx 改为内部 127.0.0.1:8081，不增加新的宿主公开端口。 |
| nats | 原始监控绑定 127.0.0.1:8222，仅同一容器网络命名空间可访问；消息客户端认证不变。 |
| nats-monitor | 新增认证代理，共享 nats 网络命名空间，监听 8822；原宿主监控端口保持回环映射，但转发到认证入口。 |
| preview | 启用 `--api-enable-basic-auth`，使用专用用户名和密码，保留回环宿主映射。 |
| api / consumer | 同步预览服务凭据；API 和两端一起切换 Cookie 认证。 |

`deploy/server/deploy.sh` 首次需要时生成独立 `PREVIEW_PASSWORD`、`NATS_MONITOR_PASSWORD`，保存到已有部署 `.env`，权限 600；保留已有非空值，不打印密码。开发脚本在 `.local-data/security.env` 同样生成和复用，不需要手工发送凭据。

新增代理只使用 Go 标准库，复用项目已有私有 Go 基础镜像构建，运行镜像为 scratch。没有引入新的公共镜像地址。Compose 配置兼容项目现有 V1 用法，本地实际解析验证使用已安装的 Compose V2；没有在生产 V1 上运行。

正式发布时先按既有方案备份并确认发布版本，然后执行：

```bash
bash deploy/server/deploy.sh upgrade all
```

本轮涉及基础设施、两端和两个后端进程，不应只升级 backend 或只替换前端。不要直接使用 restart 代替构建升级。生产入口 HTTPS、额外反向代理和历史对象 ACL 仍需要运维工作。

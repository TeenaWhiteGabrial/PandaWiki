
## 正式部署顺序（由你执行，本轮未执行）

1. 暂停写入并备份 PostgreSQL、持久卷、配置及 OSS 对象版本/副本，参照既有备份恢复方案。此次数据库迁移涉及密钥不可逆转换，先验证备份能恢复。
2. 在 `deploy/server/.env` 为 Redis/NATS 分别设置新的 URL 安全随机密码。可用 `openssl rand -hex 24` 各生成一次，不复用，不贴到日志或工单；配置文件建议权限 600。新增必填项为 `REDIS_PASSWORD`、`NATS_PASSWORD`。
3. 如用域名访问，配置 `SECURITY_ALLOWED_HOSTS`，逗号分隔、仅主机名不含端口，并包括实际内部 API 调用名称/地址。若仅用 IPv4 地址与 localhost，可沿用默认。需要单独的跨源 API 集成时，用 `SECURITY_ALLOWED_ORIGINS` 指定完整来源协议、主机和端口；普通同源访问无需配置。
4. 首次安全升级需一起更新基础设施及全部客户端/两端，使用 `bash deploy/server/deploy.sh upgrade all`。不能只更新 backend，否则旧基础设施与新凭据可能不一致；脚本会对检测到的旧匿名 Redis 阻止部分升级。Compose V1 1.29.2 使用 `docker-compose --env-file deploy/server/.env -f deploy/server/docker-compose.yml ...`；外部 OSS 环境仍按项目脚本统一加载，不直接打印整份配置。
5. 迁移 56 将旧 MCP 密钥转哈希，不要求客户端更换原密钥；旧无会话记录的账号 JWT 必须重新登录。既有密码账号也会收到首次改密提示。默认 admin 的环境密码只用于新库初始化，以后重启不再覆盖本人已经修改的密码。两端右上角提供“修改密码”入口；强制改密弹窗之外也可主动修改。
6. 用专用账号在实际 HTTPS 入口复测清单，确认上传/预览、评论、问答流、改密与重新登录。最后核对基础设施宿主端口确实只映射回环、外部防火墙无旁路。

数据库迁移 56 不能由哈希恢复出原始密钥。跨越此迁移后，升级脚本会停止不安全的自动镜像回滚；回退旧版本必须恢复升级前数据库备份并统一回退服务/配置，不能只换回旧 API 镜像。脚本仅在迁移版本可确认时允许安全范围内的镜像回滚，不自动覆盖业务数据库。

会话参数默认 `AUTH_SESSION_MAX_AGE_SECONDS=28800`、`AUTH_SESSION_IDLE_SECONDS=1800`；应按你们安全要求调整后一起部署 API。闲置依据最近有效认证请求，不是浏览器鼠标/键盘事件，页面后台自动请求也可能刷新活动时间。

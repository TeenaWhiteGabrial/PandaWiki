# 用户端登录入口与匿名访问排查

后续策略已更新：按用户确认，用户端已改为强制登录，下面 P0/P7 匿名可读的描述是调整前的历史核查结果。最新实现与验证见[强制登录改动与验证](用户端强制登录-20261026.md)。

日期：2026-10-26。仅检查本地开发服务和数据库，没有连接生产，也没有更改现有文档或栏目的权限。

排查页面：`/node/01a1616c-ad60-758d-ab86-05ffd3bf94cc`。

## 已确认的原因

1. 重复登录按钮：历史配置中的 PandaWiki 默认按钮被转换为“登录”，页面又单独渲染固定登录按钮，匿名时同时显示两个入口。
2. 当前页面为 P7 测试文档，文档和父目录都继承上级。所属栏目名为“权限验收-受限栏目-20261021”，但实际保存的是 `visible=open / visitable=open / answerable=open`，因此匿名可读。栏目名称本身不产生限制。
3. 匿名接口没有返回所有文档。本地匿名目录返回 88 个节点；P2 受限文档不在目录中，直接访问详情返回业务码 40003，正文与文件 key 均未返回，其下载签名也被拒绝。P0/P7 按现有公开配置允许读取。这是部分测试样本的结论，不能代表所有权限组合均已验证。
4. 另有前端残留风险：文档详情存在只按节点 ID 索引的模块缓存，登录失效时目录状态也未同步丢弃。旧页面可能继续显示前一身份已经加载的内容，不能据此认定当前匿名请求成功取得受限正文。

## 本次改动

- 头部只保留统一登录入口，过滤历史占位按钮和指向同一登录页的配置按钮；普通自定义业务按钮继续展示。
- 删除不区分身份的文档详情缓存。每次进入文档、身份变化或登录失效后重新请求详情，并使用 `cache: no-store`。
- 文档渲染绑定本次身份与节点；旧请求的延迟响应不能覆盖新身份页面，也不在新请求等待时继续展示上一份正文。
- 登录信息清理或其他标签页登录态改变时，立即清空旧目录、栏目及正文作用域，关闭问答弹窗，并重新加载服务端过滤后的目录。刷新获得的新目录同步到前端状态，不再只使用首次初始化的数据。
- 服务端目录请求也显式使用 `cache: no-store`。

本次保留既有“公开内容允许匿名访问”的规则。如果 P7 应当受限，需要在管理端设置对应栏目的实际查阅规则；未擅自按栏目名称改写权限。

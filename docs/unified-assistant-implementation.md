# 统一智能助手首版：实现与本地验收

日期：2026-11-03。未部署生产，未提交或推送。设计见 [第二版方案](unified-assistant-plan.md)。

## 入口

- 管理端：设置 → 智能助手设置 → PPT 模板。首版由超级管理员维护。
- 用户端：原智能问答弹窗的输入框工具栏，可上传文件、选择模板、选择授权文档/目录及切换联网。
- 文件保留在会话任务卡片中，历史会话可以恢复任务、下载或发起新版本修改；上传与生成均不自动入库、学习或公开。

## 已实现

1. 私有附件：PDF、DOCX、PPTX、XLSX、TXT、CSV及PNG/JPEG排版素材（不承诺图像语义理解）；单文件20 MB、每轮10份/100 MB，个人临时资料总额1 GB。检查实际包结构、解压规模、外部关系及类型；失败可重试解析。上传完成前不能发出依赖它的消息。
2. 附件与 PPT 模板用途分开；个人模板确认后只供本人使用。企业模板支持草稿、发布、停用、默认、版本更新、预览和部门/等级范围配置；范围修改作用于同一模板的所有版本，旧产物访问会重新检查。
3. 16:9 模板自动检测标题/正文占位符；规范副本移除旧幻灯片、备注、批注、隐藏页、原缩略图及作者信息。保留的母版图片需要上传者检查并确认。不承诺任意演示稿无损套版，暂不提供自由版式设计器。
4. Word 分级标题、正文、列表、表格和授权图片；PPT 正文、表格、授权图片、基础图表及系统/企业/个人模板；Excel 多表、格式、冻结、筛选、基础受控公式及缓存结果。生成后结构重读校验，超限拒绝，不静默截断。
5. 原始 Excel/CSV 的复制选列、分组求和和计数由程序读取原数据执行；模型规划字段，不逐格转写数千行数据。其他复杂数据处理不执行模型脚本。
6. 文件任务在取材前持久化；PostgreSQL 是队列和状态权威，独立 JetStream `PANDA_ASSISTANT` 只发唤醒通知，丢通知时数据库轮询恢复。Worker 与学习 Consumer 分开。请求去重、条件认领、递增租约 epoch、心跳、取消竞争、重试检查点与不可变对象发布均已接入。
7. 每会话同时一个文件任务、每账号最多两个。普通问答继续使用原文字 SSE；带工具请求通过后台任务卡片和 REST 状态恢复，任务接受后释放聊天输入。不会因为关闭浏览器而取消。
8. 修订绑定基础版本，保留旧文件；陈旧基础版本不能覆盖新版本。Word 按章节/段落，PPT 按幻灯片，Excel 按工作表/列。系统记录结构对象 ID，并追加真实来源记录。
9. 附件、模板、历史消息、基础产物与检查点保守传递来源依赖；生成/发布/读取/下载检查当前权限。旧无来源回答不直接用作导出正文。会话详情、继续会话和普通聊天增加账号隔离，不能靠他人会话 ID 或 nonce 复制私有历史。
10. 下载与预览通过鉴权文件流，不暴露 OSS 对象键或永久直链；继续使用项目的安全 PDF.js 组件，保留防嵌入头。Excel 提供分页工作表预览。合格文件预览失败时仍可下载。
11. 新上传未使用时保留24小时，进入任务后按配置保留（默认30天）；企业模板引用原件延长保留。产物期限不超过所依赖的个人上传资料期限。受管对象先登记再上传，周期回收无引用、无活跃任务且超过宽限期的对象。
12. 管理端原问答日志增加任务阶段、耗时、模板、来源、联网词、尝试与产物记录。模型用量在可用时计入现有统计。
13. 联网按钮按会话保存、本轮固定。当前接入 Tavily 文本检索摘要，必须填写确认可公开的检索词；不会自动外发历史、知识正文、上传文件或模板。首版不抓取任意网页全文、不执行网页脚本、不自动搜图。参考：[Tavily Search 协议](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

## 配置与运行

新增服务：

- Docker 基础设施 `document-generator`，本地 `127.0.0.1:18091`；生产仅连接隔离内部网络。
- Go 开发命令 `bash scripts/dev-assistant.sh`，日志 `.logs/backend-assistant.log`。
- 普通 API、Consumer、用户端和管理端保持原开发命令。

开发脚本自动生成并复用 `.local-data/security.env` 中的 `DOCUMENT_GENERATOR_TOKEN`；生产部署脚本自动补齐同名内部凭据，不修改已有 Redis/NATS 密码。

可选：`ASSISTANT_SEARCH_API_KEY`（Tavily）、`ASSISTANT_RETENTION_DAYS`。本地可放根目录 `.env`，生产放 `deploy/server/.env`。留空搜索密钥时禁用联网，不影响其他功能。

生产涉及 API、Consumer（同步模型结构）、assistant-worker、document-generator、管理端和用户端；已更新 Compose 与 `upgrade backend/all` 服务组。不要只部署前端。数据库迁移58只新增助手表和消息来源字段，不删除原文档或索引。

2026-11-03 补充修复学习上传 404：用户显式重新学习时，先核对目标数据集；存在则复用，确实缺失则用当前配置的向量模型创建独立绑定并持久化。数据库锁串行化并发初始化，查询失败不误判为丢失，已有模型重建时不擅自切换绑定；初始化本身不创建任何文档学习任务。Consumer 同时覆盖普通发布消息，旧的显式绑定任务不会被静默转移。回滚事务测试覆盖复用、缺失、查询/创建失败、重复调用与不提交全库任务；本地实际重试一篇「数字孪生验收文档」，正文上传、向量生成和写入完成，PandaWiki 与 RAGLite 均返回成功。该单篇学习验证不代表全库索引或 PPT 实际模型生成已经完成。

## 生成质量流程（2026-11-03）

新建 Word、PPT、Excel 任务在生成前增加三步：

1. 根据原始要求、会话历史与实际资料判断是否需要澄清。每轮至多3问，提供推荐设置；已回答的问题不再按相同 ID 重问，最多2轮澄清，明确的修订不机械追问。
2. 先检查实际正文、解析范围及主题覆盖，再判断能否制作正式内容。模板、仅文件名/元信息、过短正文不作为充分依据。缺项在对话中列明，允许选择有权限的已发布文档直接取材、上传附件或补充事实；主动补充的事实标为用户说明，不冒充外部核验结果。需要带占位符的结果时，必须明确点击「仅生成框架草稿」，文件标题与完成说明由程序确保带有草稿标记。
3. 在原任务卡片展示大纲、核心观点、依据和资料覆盖。用户可编辑各部分标题与重点，或填写意见重新规划；点击「确认大纲，生成文件」后再生成。PPT正文页数需与大纲一致，系统来源页另加。明确的既有文件修订可以直接继续，保留版本机制。

等待状态 `awaiting_input` / `awaiting_sources` / `awaiting_outline` 存在既有 `assistant_runs.checkpoint` 中，无新增数据库迁移。刷新、重新打开历史会话后可以继续；补充操作还会写入普通会话记录。聊天框中的回复也会继续同一等待任务，确认类短句可确认当前服务端大纲，其他意见重新规划。卡片中尚未提交的本地编辑以卡片确认按钮为准。

继续操作检查账号、会话、来源当前权限、计划版本和请求幂等性；确认期间不能并行新建同会话任务，失败任务重试也不能绕过这一限制。等待阶段不被 Worker 反复认领，仍可取消。确认后复用已审核资料快照，不再次检索替换素材；正式生成与发布前继续执行来源权限校验。

资料充分与主题相关性的语义判断由模型执行，程序额外检查资料类型、最小正文、来源 ID、可用事实来源、问题数量、轮次、支持规模、格式和页数，以及明显占位标题。它不是逐句事实证明，也不承诺仅靠提示词就消除幻觉；复杂版式仍受现有 Office 渲染器限制。

本地新增回归：完整澄清→资料不足→补充说明→编辑/确认大纲、刷新读取、重复请求、过期计划、跨账号/知识库、撤销来源、取消后的迟到操作、显式框架草稿、等待任务与重试冲突。使用仅复制表结构的隔离测试库，事务回滚，不写真实 OSS。

真实配置模型的合成样本验证：缺少产品正文时进入补充资料；明确受众/目的/页数且有事实时进入三部分大纲确认；模糊客户演示请求返回3个关键问题。第一次模糊样本请求在100秒测试等待上限超时，收紧“资料不足或需澄清时不展开大纲”的提示后复测29.56秒通过；单次结果不代表响应时间保证。大纲确认后的真实文件服务渲染、模板、私有下载及来源撤销回归同时通过。2026-11-03 已重载本地API与助手Worker，未动学习Consumer或Docker数据卷；重载前后9个栏目、180个节点、16名用户保持一致。

2026-11-03 需求计划解析兼容修复：接受单个完整JSON对象的代码围栏、额外说明和已闭合思考包装；拒绝截断、多个对象、错误字段类型，不通过补括号或强制转型猜测内容。格式错误最多自动修正一次，明确的token上限截断使用更高输出预算重试。私有检查点保留有界失败响应，用户接口不暴露该内容；管理端日志仅追加响应长度、哈希、结束原因、解析错误和修正次数，便于区分格式错误与输出截断。本地隔离测试覆盖上述异常及无效响应不产出文件。

原任务 `e1d9d0de-8264-46ed-ade2-5b151ad9dd83` 的本地重试复现：首次规划响应 `finish_reason=length` 且正式响应正文为0字节。旧实现把该情况归为通用JSON格式错误。规划输出额度现为12000 token，明确截断时仅自动重试一次并提升到16000；诊断同时记录请求额度、实际用量和思考内容字符数（不记录思考原文）。

同一任务后续重试在12000 token额度内返回完整JSON，但暴露Excel规划超出4个数据工作表的约束遗漏。已将该上限明确写入规划提示，并将规划语义/支持规模校验纳入同一次有界自动修正；有效JSON但无效规划会单独记录validation_error。通过校验的响应也会立即持久化新诊断，防止后续验证报错时沿用上一轮诊断。本地隔离回归验证超限规划能够修正，以及旧诊断被新结果替换。

## 用户端助手反馈规则（2026-11-03）

用户端任务、附件、规划操作、问答流和预览不直接展示技术异常、失败阶段、内部任务编号或红色错误弹窗。内部failed状态在任务卡片呈现为“已暂停”，保留继续处理与结束任务；来源撤权仍如实提示重新选择可访问资料，资料不足继续按对话澄清。服务器真实状态、异常原因和诊断继续供管理端日志使用，没有将失败伪装成完成。附件下载先校验文件响应，防止导航到API错误文档；临时网络问题显示中性状态说明。普通问答中断保留已展示的回答，说明当前已暂停。

暂停任务可通过原取消接口结束，取消保留内部诊断；回归验证仅目标任务改变，其他任务保持原样，已结束任务不可重试复活。此次是用户端反馈与任务操作调整，长文件按章节/页分批生成、自动断点续作仍未实现，不对用户显示虚构的分段进度。

## 知识库目录册与正式内容诊断（2026-11-03）

本地实际日志表明，目录导出原先误走相关性检索，仅向模型提供少量命中文档，随后反复索要完整清单和文件大小；目录任务并不需要模型重写数据库已有信息。明确要求知识库文档清单/目录册的 Excel 新建任务现走程序化导出：读取与用户端目录相同的当前发布快照，批量计算当前账号查阅权限，保留同名但不同ID的文档、尚未学习的文档和仅元信息文件；指定资料范围不会扩大。目录路径使用发布名称，受限祖先不泄露名称，兼容历史 `nav:<id>` 栏目根节点。此类明确的元数据导出直接生成，无需再做业务大纲澄清；上传表格、普通产品内容和既有文件修订保留原流程。

文件大小通过已授权原文件对象的 HEAD 查询获取，6路并发、单次3秒、总预算20秒；旧 MinIO 文件不存在、无原文件或读取失败时保留空值及原因，绝不伪造为0，也不阻断清单。每1000份文档分页到新工作表，保留真实行数和源ID；目录专用工作簿最多25表（含说明和来源），超出时明确停止，不截断。完整依赖保存在私有任务记录中，预览、下载与发布均复查查阅权限；不要求该文档已建立向量索引或允许问答。任务卡片显示文档总数，避免铺满全部文件名。

正式内容生成也采用完整JSON兼容解析，明确截断后在有界重试中提高额度，其他格式/规划约束错误至多自动修正一次。新增 `content_generation_diagnostics` 记录预算、用量、结束原因、响应长度/哈希及校验原因；有界失败正文仅保留在私有检查点。没有把解析失败伪装成生成成功，也尚未实现通用长文件的逐章节断点生成。

验证：隔离库测试覆盖2005份分页、同名文件、未知大小、无索引/元信息文件、发布版本和个人权限/撤回；真实本地 Office 渲染、内存私有对象存储和下载链路验证23份清单逐行无丢失。本地只读对照当前账号 `ptdevg1` 的126份发布文档，现有逐文档查阅策略和目录策略均返回62份。

# 目录按层加载

管理端文档树、资源管理器、编辑器目录和用户端目录使用按需加载。进入页面先返回栏目；展开栏目或文件夹时返回直属节点。文档直达链接另外补齐祖先路径和路径各层的兄弟节点，不递归下载无关分支。

## 接口

- 管理端：`POST /api/v1/node/tree`，JSON 参数为 `kb_id`，以及可选的 `nav_id`、`parent_id`、`path_id`、`search`、`parents`。
- 用户端：`GET /share/v1/node/tree`，知识库由现有会话/请求头确定，可选查询参数为 `nav_id`、`parent_id`、`path_id`、`search`。
- 索引状态：`POST /api/v1/node/tree/status`，JSON 参数为 `kb_id`、`ids`，每次最多 1000 个节点，只返回当前管理员可管理节点的 ID、发布状态和索引状态。

不传节点范围时，只返回栏目，`list` 为空。`has_children` 根据当前请求有权看到的节点计算；`loaded_parents` 标识本次已完成查询的层级（空字符串表示栏目直属层级）；`tree_revision` 用于发现权限/目录结构发生变化。管理端使用 POST 批量刷新已加载层级，避免展开很多文件夹后 URL 过长。

原有完整目录接口继续保留，供移动目录等完整选择器使用。索引进度面板打开时独立查询完整任务列表，不依赖目录已经展开到哪一级。

## 权限与缓存

服务端每次请求都会读取当前权限并计算可见范围。为保留多层权限交集与历史授权的定位路径，需要读取轻量的权限/父子关系图；名称、文件信息、索引进度、权限标签等目录展示数据只查询当前需要的节点 ID。没有跨请求共享的服务端权限缓存。

用户端不会在目录响应中返回存储键或授权规则。仅用于定位的祖先文件夹只显示必要名称和结构，不提供正文、摘要或存储信息。

浏览器缓存属于当前页面和当前身份：已加载分支再次展开不请求，未完成的同分支请求复用，失败可以原位重试。账号切换时清空缓存并丢弃旧请求响应；新请求发现权限版本变化时重新校验缓存。返回浏览器标签页时也会重新校验。文档正文和问答仍由各自接口独立鉴权。

加载提示位于展开后的子区域，文件夹图标保持稳定。搜索由服务端检索全部有权访问的内容，并补齐祖先路径，不限定于已加载分支。用户端移动目录搜索结果只展开搜索路径，不自动下载完整子树。

## 验证

- Go 用例 `TestSelectTreeLevel`：层级选择、文档直达、搜索路径、批量刷新、跨栏目和异常循环。
- Go 用例 `TestDocumentTreeQueriesPostgres`：245 个节点的回滚事务；检查两端的浅层响应、全局搜索、管理范围、存储信息隔离、收回权限、目录详情直属列表与原有完整接口。
- 前端类型检查：管理端与用户端的 TypeScript 检查。
- 本地浏览器隔离组件验证：初始请求一次，展开栏目及一个文件夹后共三次；折叠后重开不增加请求；失败后原位重试；切换身份后不接受旧请求。

PostgreSQL 测试需设置 `PANDA_WIKI_TEST_PG_DSN` 为本地测试库地址。测试数据位于回滚事务内，不写入生产环境。

## 部署

更新 API、管理端和用户端。无需增加基础设施、修改存储配置或执行数据库迁移。前后端应一起更新，以提供新的目录树接口。
